## Changes

- The D1 transfer sends the complete immutable snapshot in one import request.
  Data and its receipt commit in one transaction. Exact integer encodings remain intact.
- The existing driver progresses through activation immediately. It runs independent
  custody transfers and presignature settlement concurrently. It skips completed work
  and uses exact import acknowledgements to advance within an invocation.
- A lost acknowledgement discards the local cursor. The next attempt reads the
  destination's durable cursor. Custody formats, ownership fences, and physical routing
  remain unchanged. Cleanup remains separate from activation.
- Relocation uses the SDK's existing interactive request policy. Preparation and owner
  confirmation can exceed the former request deadline before the pause target expires.

Each transfer attempt used one D1 export and one D1 import. Cron overlap produced
one exact retry per direction: two exports and two imports in each direction.
The repeated payloads had identical sizes. Local fault coverage verifies that
duplicate imports return the same receipt without repeating data effects.

The supported D1 payload is at most 512 KiB and 80 encoded chunks. Admission checks
capacity before pause. Internal encoding segments remain inside the single payload.
There is no streaming fallback, new migration, new service, or new environment variable.
Routine signing/refill routing and ordinary-lock presignature retention are unchanged.
